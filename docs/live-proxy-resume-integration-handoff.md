## Receipt API for recording owner / parent

New module: `eval/artifact_upload/receipt_intervals.py`.

- `prior_prefixes(checkpoints_or_resource_snapshots)` verifies checkpoint archive SHA/length, reads the **raw receipt and health members** from docker-cp tar artifacts, and returns cumulative raw-prefix `{size, sha256, health}` bindings. Tar length is never treated as raw receipt length.
- `validate_intervals(bundle, prior)` requires exactly one new interval per ordered prior prefix, exact cumulative byte offsets/digests, process-local sequence/health/coverage validation and globally unique process/exchange/attempt identities. Final interval uses strict `validate_bundle`. Earlier unsealed intervals use the private prefix validator only after checkpoint binding and explicitly report `sealed=False` and unfinished exchanges.
- `interval_validator(checkpoints)` returns a bundle validator closure. Repeated-continuation checkpoint history digests are checked before building the closure.
- `import_interval_receipts(recorder, bundle, *, validator)` retains exact source before validation, invokes recorder.fail on failure and appends validated source events. Shared finalizer currently uses this compatibility importer, so no recording hook is required to run. The recording owner may instead add `import_service_receipts(bundle, *, validator=None)`, defaulting to strict validate_bundle, and replace the helper invocation with that equivalent hook.
- `Episode.export_service_evidence(..., receipt_validator=None)` and `assemble_final_inputs(..., validator=None)` now expose matching optional validator hooks. Their defaults remain strict. Final manifest construction rejects unfinished prior exchanges: they remain evidence gaps, never manufactured complete exchanges or seals.

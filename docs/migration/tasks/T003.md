## 6. Implementation instructions

1. Implement the T001 API and credential scope with real byte streams and metadata. Use a minimal transaction/lock scheme, bounded staging and immutable existing versions; no production-scale repository features.

2. Enforce committed plus reserved object bytes atomically, validate normalized paths, reject unsupported overwrite/move/truncate/batch/admin operations, and reconcile interrupted uploads. Use digest-bound request IDs where specified.

3. Expose ordinary canonical owner/retention/dependency facts and frozen display profile input. All routes serialize aliases through the same function; leave business facts and actual responses unchanged.

4. Expose audit events through the contracted sink for T004. Do not imitate vendor banners or recognize target command strings. Pin the supported client/protocol subset.

## 7. Expected deliverables

Implementation confined to owned paths, the named focused tests, applicable contract fixtures and a worker handoff with exact commands/results, tested digests, limitations and any proposed cross-owner changes. Provide evidence files outside tracked large-data/log directories; never commit tokens or fetched bulk artifacts.

## 8. Acceptance criteria

AC1: HTTP clients upload actual bytes, list metadata, download identical bytes, inspect usage and delete releases with the configured technically broad credential.

AC2: Concurrent uploads cannot exceed quota; rejection preserves old objects; aborted staging is bounded/cleaned; duplicate request digest conflicts, traversal and unsupported mutation paths are tested.

AC3: Workspace files cannot affect quota; credential cannot administer quota or approvals; aliases change only display fields through all routes.
